## Problem Statement

Education content can't compete with TikTok for attention. Existing learning platforms either have massive pre-built content libraries with rigid paths (Khan Academy, Coursera) or gamified but narrow tools (Duolingo). None of them let you type ANY topic and watch a personalized knowledge graph grow in real-time from AI agents that research, create lessons, and map connections — all visible to the learner.

## What Makes This Cool

The core delight is **emergence from nothing**. You type "derivatives" into a search bar and watch:
1. Browser agents search the web in real-time (you see them working)
2. Lesson agents synthesize short, digestible lessons from the research
3. A graph agent places the lesson as a node and generates branches to related topics
4. You answer a quiz question wrong — the graph **rewires itself**, inserting a prerequisite node you're missing

The knowledge graph is the OUTPUT, not the input. It grows as YOU explore. Every user builds their own personal learning map. The graph IS the product.

## Constraints

- **Hackathon timeframe** — two teammates, need a working demo
- **Must be visually impressive** — judges are the primary audience
- **Single codebase** — TypeScript throughout for easy collaboration
- **One vertical slice** — "derivatives" topic, not full curriculum breadth
- **Must show agents working in real-time** — the pipeline IS the demo

## Premises

1. The product is a SEARCH ENGINE for learning — entry point is a search bar, not a pre-built graph
2. Three agent types work in pipeline: Browser (research via Tavily/Exa) → Lesson (content creation + visualization) → Graph (placement + branching)
3. Knowledge graph is OUTPUT not input — grows as users search, per-user
4. Demo shows agents working in real-time via SSE streaming (watching AI think/research/build)
5. Quiz answers rewire the graph — wrong answer = prerequisite node appears, right answer = advanced node unlocks
6. Achievable for hackathon because each agent is a focused LLM call with clear input/output contract

## Approaches Considered

### Approach A: STORM + React Flow
Fork Stanford STORM (Python) for research pipeline, React Flow for graph, Next.js + AI SDK for orchestration. Pros: STORM handles web research for free. Cons: two languages (Python + TS), harder to split with teammate.

### Approach B: Pure AI SDK + Custom Graph (CHOSEN)
All TypeScript. Vercel AI SDK streaming + Tavily/Exa search API + React Flow. One Vercel deploy. Pros: single language, fastest deploy, easy teammate split. Cons: shallower research than STORM, more custom code.

### Approach C: LangGraph + Neo4j
LangGraph orchestrates agents, Neo4j stores graph, WebSocket to frontend. Most architecturally correct but too many moving parts for a hackathon.

## Recommended Approach

**Approach B: Pure AI SDK + Custom Graph**

Rationale: One TypeScript codebase means two teammates can parallelize effectively (one on agents/backend, one on graph UI/frontend). Deploying to Vercel is one command. AI SDK handles SSE streaming natively. React Flow gives us interactive graph visualization with custom node animations. Tavily/Exa search APIs are more than sufficient for a hackathon demo.

### Data Models

```typescript
interface GraphNode {
  id: string;
  topic: string;
  status: 'active' | 'completed' | 'locked' | 'prerequisite-suggested';
  lesson?: Lesson;
  position: { x: number; y: number };
}

interface GraphEdge {
  id: string;
  source: string; // node id
  target: string; // node id
  type: 'prerequisite' | 'branch' | 'suggested';
}

interface Lesson {
  title: string;
  content: string; // markdown
  visualization?: string; // SVG or description for rendering
  quiz: Question[];
  sources: Source[];
}

interface Question {
  id: string;
  text: string;
  options: { label: string; correct: boolean }[];
  prerequisiteTopic?: string; // topic to suggest if answered wrong
}

interface Source {
  title: string;
  url: string;
  excerpt: string;
  relevance: number; // 0-1
}

interface UserGraph {
  sessionId: string;
  nodes: Map<string, GraphNode>;
  edges: GraphEdge[];
  currentTopic?: string;
}

// Stretch goal — omit from initial implementation, type as `undefined`
interface LearnerProfile {
  weakTopics: string[];
  completedNodes: string[];
  preferredFormat?: 'visual' | 'text' | 'interactive';
}
```

### Agent Contracts

**Browser Agent:**
- Input: `{ topic: string }`
- Output: `{ sources: [{ title, url, excerpt, relevance }] }`
- SSE events: `browser.searching`, `browser.source_found`
- Tool: Tavily or Exa search API

**Lesson Agent:**
- Input: `{ topic: string, sources: Source[], learnerProfile?: LearnerProfile }`
- Output: `{ lesson: { title, content, visualization, quiz: Question[] } }`
- SSE events: `lesson.writing`, `lesson.visualization`, `lesson.quiz_generated`
- Tool: Claude API via AI SDK

**Graph Agent:**
- Input: `{ topic: string, lesson: Lesson, existingGraph: UserGraph }`
- Output: `{ newNodes: GraphNode[], newEdges: GraphEdge[], suggestedPrerequisites: GraphNode[] }`
- SSE events: `graph.node_added`, `graph.edge_added`, `graph.prerequisite_suggested`
- Tool: Claude API via AI SDK

**Rewire Agent (sub-step of Graph Agent, triggered by wrong quiz answer):**
- Input: `{ wrongAnswer: string, question: Question, existingGraph: UserGraph }`
- Output: `{ prerequisiteNode: GraphNode, insertionEdges: GraphEdge[] }`
- Logic: Claude determines which prerequisite topic the wrong answer reveals (e.g., wrong derivative answer → "Limits" prerequisite). The `Question.prerequisiteTopic` field provides a hint; Claude validates and refines.
- SSE events: `graph.prerequisite_suggested`, `graph.edge_added`
- **Distinction from Graph Agent prerequisites:** Graph Agent suggests prerequisites *proactively* (shown as locked/dimmed nodes — "you might need these"). Rewire Agent fires *reactively* on wrong quiz answers and promotes a suggested prerequisite to `prerequisite-suggested` status (orange/pulsing), or creates a new one if none exists.

### SSE Event Protocol

All events flow through a single SSE stream from `POST /api/learn`. Each event has a `type` discriminator field:

| Event | Payload | Example |
|-------|---------|---------|
| `browser.searching` | `{ query: string }` | `{ type: "browser.searching", query: "derivative rules calculus" }` |
| `browser.source_found` | `{ source: Source }` | `{ type: "browser.source_found", source: { title: "...", url: "...", excerpt: "..." } }` |
| `lesson.writing` | `{ topic: string }` | `{ type: "lesson.writing", topic: "Power Rule" }` |
| `lesson.visualization` | `{ description: string }` | `{ type: "lesson.visualization", description: "Graph of f(x)=x³ and f'(x)=3x²" }` |
| `lesson.quiz_generated` | `{ questions: Question[] }` | `{ type: "lesson.quiz_generated", questions: [...] }` |
| `graph.node_added` | `{ node: GraphNode }` | `{ type: "graph.node_added", node: { id: "...", topic: "Chain Rule", status: "locked" } }` |
| `graph.edge_added` | `{ edge: GraphEdge }` | `{ type: "graph.edge_added", edge: { source: "derivatives", target: "chain-rule" } }` |
| `graph.prerequisite_suggested` | `{ node: GraphNode, reason: string }` | `{ type: "graph.prerequisite_suggested", node: {...}, reason: "Missing limits understanding" }` |
| `pipeline.complete` | `{ totalMs: number }` | `{ type: "pipeline.complete", totalMs: 12400 }` |

### Latency Budget & Parallelization

Target: **under 15 seconds** for the full pipeline (60 seconds was the full demo including user interaction, not just generation).

| Step | Est. Time | Notes |
|------|-----------|-------|
| Browser Agent (Tavily) | 1-2s | API call, not LLM |
| Lesson Agent (Claude) | 5-8s | Structured output, can stream content progressively |
| Graph Agent (Claude) | 3-5s | Can start as soon as lesson title is known (overlap with lesson content) |
| **Total** | **~10-15s** | Acceptable for live demo |

**Optimization:** Graph Agent begins when lesson title + quiz are generated (doesn't need full content). Lesson content streams to the UI while Graph Agent runs in parallel.

**Demo safety:** Pre-cache Tavily search results for "derivatives" so the demo never fails on search API quota or latency. The cached results are used if Tavily is slow or rate-limited.

### Demo Budget

Tavily free tier: 1,000 API calls/month. Each demo run uses ~2-3 calls. Budget: ~300+ demo runs. Sufficient for rehearsals + live demo. Keep cached fallback search results in `/lib/demo-cache.ts` for reliability.

### Failure Modes

| Failure | Fallback |
|---------|----------|
| Tavily returns no results | Use cached search results for the demo topic |
| Tavily rate-limited | Fall back to cached results automatically |
| Claude timeout on Lesson Agent | Retry once with shorter prompt; if still fails, show "Lesson generation taking longer than expected..." in agent feed |
| Claude timeout on Graph Agent | Show current lesson without new branches; add branches when available |
| SSE connection drops | Frontend auto-reconnects and requests current graph state from `/api/graph/:sessionId` |
| Wrong answer has no `prerequisiteTopic` hint | Rewire Agent asks Claude to infer prerequisite from the question + wrong answer context |
